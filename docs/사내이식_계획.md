## 0. 배경 한 장 요약

- **외부판**(이 저장소): 개인 계정 기반 — Supabase + Anthropic API + 텔레그램 + 네이버 API +
  PC 스케줄러. 운영자 개인과 팀원 소수가 사용. **계속 운영·진화한다.**
- **사내판**(새로 만들 것): 회사 인프라(Playground)에서 도는 별도 시스템. 팀 공식 도구화가 목표.
- 두 시스템은 저장소도 히스토리도 분리하고, 외부판의 개선을 **기능 단위로 선별 이식**한다.

### 기계·저장소 경계 (혼동 금지)

| | 외부판 | 사내판 |
|---|---|---|
| 저장소 | gitlab.com (GitLab사 공개 서비스, **개인 계정**) | gitlab.tde.sktelecom.com (SKT 사내 GitLab, **회사 계정**) |
| 개발 기계 | 회사 Windows PC (운영 겸용) | **맥북** (사내용 개발 전담) |
| 실행 위치 | PC 스케줄러 + Supabase | Playground (배포·확인은 mydesk 안에서) |

- 두 GitLab은 이름만 같은 **완전 별개 서비스**다. 개인 키·개인 봇은 개인 쪽에만,
  회사 코드는 회사 쪽에만.
- 맥북이 사내용 개발 전담인 이유: **mydesk 화면을 Claude에게 보여줄 수 있는 유일한 기계**
  (업무PC는 mydesk 캡처 차단). Playground 첫 구축기에는 화면 공유가 잦다.
- mydesk로의 파일 반입은 불가 — **코드·데이터는 오직 TDE GitLab 경유**로 들어간다.
- **mydesk 밖으로 텍스트 클립보드 복사도 불가** (2026-08-21 운영자 실측 — 아래 '첫날 확인' 1번의
  답). 에러 로그를 글자로 긁어 나올 수 없다 → 즉석 확인은 **화면 캡처(맥북)**, 긴 로그는
  **mydesk 안에서 파일로 저장 → TDE GitLab push → 맥북에서 pull** 두 갈래로 나른다.
  GitLab은 반입 통로이자 **유일한 텍스트 반출 통로**다.
- MyDesk 안에서 Claude Code 실행 불가 (2026-08-19 운영자 확인).

## 1. 맥북 셋업 (최초 1회)

1. Claude Code 설치: https://code.claude.com/docs 안내에 따라 설치
   (`npm install -g @anthropic-ai/claude-code` 또는 네이티브 설치) → 기존 Claude 계정 로그인
   (같은 구독으로 기기 추가 비용 없음)
2. 도구: `brew install git python@3.12`
3. 외부판 clone (참조용): `git clone https://gitlab.com/<그룹>/radio-policy-ai.git`
   - 스모크 테스트로 개발기 성립 확인: `python3 -m unittest discover -s tests` (17건, 네트워크 불필요)
4. TDE GitLab 접속 설정: gitlab.tde.sktelecom.com 로그인(회사 계정) → 사내판 프로젝트 생성
   (아래 3장) → clone
5. 새 Claude 세션 시작 → 첫 마디: **"docs/사내이식_계획.md 읽고 시작하자"**

`.env`(외부판 키)는 참조용 clone에는 필요 없다. 사내판은 키 자체가 다르며
Playground KMS에 등록한다(외부판 키를 사내에 가져가지 않는다).

## 2. Playground에서 확인된 것 (매뉴얼 분석 결과 — 재조사 불필요)

| 알림 | **TOKTOK Message** — 수신자 @sk.com 이메일(콤마 구분). outbound GW로도 발송 가능(`api.toktokmessenger.sk.com` 경유, p.243). SMS/MMS는 OpenAPI 사용신청 필요 | p.243, 306 |

## 3. 착수 순서

### A. 첫날 확인 (mydesk에서, 30분)

1. ~~mydesk에서 텍스트 클립보드 복사(사내→밖)가 되는가~~ → **안 됨 (2026-08-21 실측 완료)**.
   대응: 디버깅 산출물 중 짧은 것(에러 화면)은 맥북 캡처로, 긴 것(로그 파일·쿼리 결과)은
   mydesk 안에서 파일 저장 → 사내판 저장소(또는 `radio-policy-data`)에 push → 맥북 pull.
   사내판 스크립트는 처음부터 **로그를 파일로도 남기게** 만들 것(캡처 한 장에 안 담긴다).
2. TDE GitLab에 사내판 프로젝트 생성: 예 `radio-policy-internal` (private).
   데이터 반입용 저장소도 별도로: 예 `radio-policy-data`.
3. **outbound GW 추가 오픈 신청** (담당자 안태형님): ①www.law.go.kr (법제처 DRF —
   `lawSearch.do`/`lawService.do`) ②open.assembly.go.kr (열린국회정보)
   ③opinion.lawmaking.go.kr (입법예고) ④부처 보도자료: msit.go.kr, rra.go.kr, kcc.go.kr(
   현 kmcc.go.kr — 방송미디어통신위), crms.go.kr(전파관리소), etri.re.kr, kisdi.re.kr.
   — 승인 대기 중에도 **네이버 뉴스 경로는 이미 열려 있어** B~D 진행 가능.
4. Playground MCP를 맥북 Claude Code에서 시험 (`claude mcp add --transport http -s local
   playground-mcp https://playground.sktelecom.com/mcp/playground`) — 사내망 전용이라
   실패 예상, 되면 보너스.

### B. 어댑터 교체 (코드는 맥북에서 작성 → TDE GitLab push → mydesk에서 배포)

외부판 코드는 이미 어댑터 구조로 분리돼 있다. 갈아끼울 곳:

| 외부판 | 사내판 | 손댈 파일 |
|---|---|---|
| Supabase DB (PostgREST) | PostgreSQL 직결(psycopg) | `sb_client.py` — 스키마는 유지 |
| pgvector `match_chunks_semantic` 등 RPC | Qdrant 질의 | 검색 함수부 — **RRF(K=60)·article_no 가점 등 랭킹 로직은 그대로** |
| Anthropic API 직접 호출 (Haiku 판정·Sonnet 자문) | Agent API Key 게이트웨이 | `crawler.py`의 판정 호출부 등 — **프롬프트·기준문은 에이전트 설정으로 이동, 내용 무수정** |
| Voyage 임베딩 | Playground Embedding Model | `embed_util.py` |
| 텔레그램 (`notify.send_telegram`) | TOKTOK | `notify.py` |
| PC 스케줄러 + pg_cron | Playground CronJob (Diyfile `cronjobs:`) | 잡 목록은 지침의 pg_cron 표 재사용 |
| 네이버 API 직접 호출 | GW 프리픽스 (`https://outbound-api-gw.playground/openapi.naver.com/...`) | 크롤러 fetch부 |

⚠️ GW 경유 호출은 매뉴얼이 SSL 검증 끄기(`verify=False`)를 안내(p.252) — **사내판 어댑터에서만**
쓰고 외부판에 역수입 금지.
⚠️ 대시보드(app.js)는 Supabase 직접 호출부를 사내 Flask API 경유로 바꿔야 한다(anon key 개념이
없어짐 — 오히려 보안 개선).

### C. 데이터 이관 (Supabase → 사내)

- **원문·메타데이터만** 반출 — `export_document_chunks.py`(외부판 루트에 있음) 확장:
  document_chunks(법령·보도자료·회의록 원문), news_feed 필요분, app_config 기준문들.
- **임베딩 벡터는 옮기지 않는다** — 질의 임베딩을 Playground 모델로 만들므로 문서 벡터도
  같은 모델이어야 비교가 성립. 반입 후 `backfill_embeddings.py`(어댑터 교체판)로 전량 재생성.
- 반입 경로: JSONL을 50MB 단위 분할 → `radio-policy-data` 저장소에 push → mydesk에서 pull.
- 검증: 테이블별 count 대조 + 표본 10건 내용 일치 + 대표 질의("기지국 개설 허가 절차")의
  검색 결과를 외부판과 비교.

### D. 세로 관통 → 확장

뉴스 크롤러 1개로 **수집(GW)→판정(Agent API)→저장(PG)→알림(TOKTOK)** 1사이클을 성공시킨 뒤
나머지(법령·국회·브리핑·RAG 자문·대시보드)로 확장. 사내판 CLAUDE.md는 외부판과의 **차이만**
적고, 지침·배경역사 문서는 복사해 간다(함정 목록이 그대로 유효).

### E. 지속 동기화 (외부판 → 사내판)

- 이식 단위는 커밋이 아니라 **기능**. 사내판 커밋에 외부판 배경역사 번호 인용:
  `이식: 외부판 #101 시제 가드`.
- **이식 대상**: 프롬프트·판정 기준문, 크롤러 파서 수정, DB 스키마, RAG 랭킹, 새 함정 문서.
- **이식 제외**: Supabase Edge Function, 텔레그램 형식, pg_cron 등록, GitHub/GitLab CI 설정.
- 주기는 정하지 않는다 — 운영자가 "사내판에 이식하자"고 트리거.

## 4. 하지 않는 것

- 외부판의 대규모 리팩토링(공용 코어 패키지化) — 1인 운영에 추상 계층은 유지비만 늘린다.
- 크롤러를 GitLab CI(어느 쪽이든)로 옮기기 — 매시간 수집은 CI 무료 한도 초과.
- 외부판 키·토큰·챗ID를 사내 저장소에 넣기 — 사내판 시크릿은 Playground KMS에서 새로.

## 5. 운영 원칙 (외부판에서 검증된 것 — 그대로 적용)

- 판정·필터·삭제 로직에는 "틀렸을 때 보이는 로그"를 함께 만든다 (조용한 실패 금지).
- `select` 컬럼 목록에 조건 컬럼 누락 금지, 전량 조회는 페이지네이션+`order` 필수.
- LLM 판정 프롬프트에는 시제 가드·현지어 검색 지시 유지 (외부판 #101).
- 문서 규칙: 구조·스케줄·제약이 바뀌면 사내판 CLAUDE.md와 이 문서를 함께 갱신.
