## 0. 배경 한 장 요약

- **외부판**(이 저장소): 개인 계정 기반 — Supabase + Anthropic API + 텔레그램 + 네이버 API +
  PC 스케줄러. 운영자 개인과 팀원 소수가 사용. **계속 운영·진화한다.** 모든 로직(수집·판정·
  브리핑·국회·관계도)의 원본은 여기 하나뿐이다.
- **사내판**(새로 만들 것): 외부판을 다시 만드는 것이 **아니다**. 외부판 지식베이스(법령·고시·
  보도자료·회의록)에 **사내 문서를 더해** 근거로 삼는 **AI 자문 조회 계층 하나**다.
- **왜 축소했나(2026-09-11 운영자 결정)**: 8/19 원안은 크롤러·판정·알림·스케줄·대시보드를
  전부 사내 어댑터로 갈아끼운 두 번째 시스템이었다. 그 뒤 외부판은 #104~#154까지 50건 넘게
  바뀌었고, 1인 운영에서 두 시스템을 같은 모양으로 유지하는 것은 불가능하다. 운영자가 원하는
  것은 "지금 시스템 그대로 + 사내 문서도 근거로 쓰는 자문"이므로, **코드는 옮기지 않고 데이터만
  옮긴다.** 방향은 외부→사내 한 방향.
- 사내판에만 있는 기능: **보고서 초안 제안**. 외부판에서는 2026-09-09 삭제(#142, "사내 보고서는
  외부 서버에 두지 않는다"). 사내 문서 + Agent 조합이라 자연스럽게 사내판 몫.
- 확장(브리핑 push·수집 사내화 등)은 필요해질 때 §6 보류 항목을 되살린다.

### 기계·저장소 경계 (혼동 금지)

| | 외부판 | 사내판 |
|---|---|---|
| 저장소 | gitlab.com (GitLab사 공개 서비스, **개인 계정**) | gitlab.tde.sktelecom.com (SKT 사내 GitLab, **회사 계정**) |
| 개발 기계 | 회사 Windows PC (운영 겸용) | **맥북** (사내용 개발 전담) |
| 실행 위치 | PC 스케줄러 + Supabase | Playground (배포·확인은 mydesk 안에서) |

- 두 GitLab은 이름만 같은 **완전 별개 서비스**다. 개인 키·개인 봇은 개인 쪽에만,
  회사 코드는 회사 쪽에만.
- 맥북이 사내용 개발 전담인 이유: **mydesk 화면을 Claude에게 보여줄 수 있는 유일한 기계**
  (업무PC는 mydesk 캡처 차단). Playground 첫 구축기에는 화면 공유가 잦다.
- mydesk로의 파일 반입은 불가 — **코드·데이터는 오직 TDE GitLab 경유**로 들어간다.
- **mydesk 밖으로 텍스트 클립보드 복사도 불가** (2026-08-21 운영자 실측). 에러 로그를 글자로
  긁어 나올 수 없다 → 즉석 확인은 **화면 캡처(맥북)**, 긴 로그는 **mydesk 안에서 파일로 저장 →
  TDE GitLab push → 맥북에서 pull** 두 갈래로 나른다. GitLab은 반입 통로이자 **유일한 텍스트
  반출 통로**다.
- MyDesk 안에서 Claude Code 실행 불가 (2026-08-19 운영자 확인).
- 사내 문서는 어떤 형태로도 외부판(Supabase·gitlab.com)에 올리지 않는다(#142).

## 1. 맥북 셋업 (최초 1회) — 맥을 처음 쓰는 사람 기준

Windows에서는 Claude 데스크톱 앱의 **Code 탭에서 폴더를 열어** 세션을 시작해 왔다. 맥에서도
**같은 앱, 같은 방식**이다. 터미널에서 `claude`를 치는 CLI 방식은 쓰지 않아도 된다.

### 1-1. Windows 습관 → 맥 대응표

| Windows에서 하던 것 | 맥에서는 |
|---|---|
| 탐색기 | Finder |
| `C:\Users\SKTelecom\` | `/Users/<맥 계정명>/` — 터미널에서는 `~`로 줄여 씀 |
| 바탕화면에 폴더 만들기 | Finder → 데스크탑 → 우클릭 → 새로운 폴더 (같음) |
| PowerShell | **터미널(Terminal)** 앱 — 응용 프로그램 › 유틸리티 안 |
| 경로 구분자 `\` | `/` |
| 프로그램 설치(설치파일 실행) | **Homebrew**라는 터미널용 설치 도구를 먼저 깔고 `brew install …` |
| 숨김 파일 `.env` 보기 | Finder에서 `Cmd+Shift+.` 를 눌러야 보임 |
| Windows 자격 증명 관리자(git 인증) | 따라오지 않음 — 맥에서 새로 로그인(§1-4) |

### 1-2. 폴더 구성

홈 폴더 아래 `work` 폴더를 만들고, 저장소 세 개를 **형제 폴더**로 둔다. 서로 안에 넣지 않는다.

```
~/work/
├── radio-policy-ai/          # 외부판 참조용 clone (gitlab.com/radio-policy/radio-policy.gitlab.io)
├── radio-policy-internal/    # 사내판 코드 (gitlab.tde.sktelecom.com)
└── radio-policy-data/        # 외부→사내 반입 데이터 JSONL (gitlab.tde.sktelecom.com)
```

- 외부판 `.env`(키 파일)는 맥북에 **복사하지 않는다**. 참조 clone은 키 없이 읽을 수 있고
  스모크 테스트도 키가 필요 없다. 사내판 시크릿은 Playground KMS에서 새로 만든다.
- Claude 세션은 **사내판 폴더(`radio-policy-internal`)에서** 연다. 폴더를 열면 그 폴더의
  CLAUDE.md만 자동 로드되므로 사내판에 별도 CLAUDE.md를 만들고, 첫 줄에 외부판 폴더 경로
  (`../radio-policy-ai`)와 이 계획 문서 위치를 적어 둔다. 외부판 코드를 같은 세션에서 보게
  하려면 시작 시 `--add-dir ../radio-policy-ai`.
- 맥 계정명은 `SKTelecom`이 아니므로 절대 경로가 다르다. 사내판 코드에 Windows 전체 경로
  (`C:\Users\SKTelecom\...`)가 남아 있으면 안 된다. 외부판의 "Python 3.12 전체 경로" 규칙(#22)은
  Windows 전용 함정이라 맥에는 해당 없음 — `python3`가 brew 설치본을 가리키는지만 확인.

### 1-3. 순서

1. **Claude 앱 설치·로그인** — claude.ai/download 에서 Mac용 Claude 앱 설치 → 기존 계정 로그인
   (같은 구독, 기기 추가 비용 없음). Supabase MCP 등 도구 연결은 계정에 붙어 있어 그대로
   따라온다(사내판 개발에는 필요 없음).
2. **터미널을 열고 Homebrew 설치** — https://brew.sh 첫 화면의 설치 한 줄을 붙여 넣는다.
   맥에서 직접 쳐야 하는 명령은 사실상 이것 하나다.
3. **도구 설치**: `brew install git python@3.12`
4. **폴더 만들기·외부판 clone**(참조용):
   ```bash
   mkdir -p ~/work && cd ~/work
   git clone https://gitlab.com/radio-policy/radio-policy.gitlab.io.git radio-policy-ai
   ```
   개발기 성립 확인 — 스모크 테스트(네트워크·키 불필요, 2026-09-11 기준 53건):
   ```bash
   cd ~/work/radio-policy-ai && python3 -m unittest discover -s tests
   ```
5. **TDE GitLab**(gitlab.tde.sktelecom.com, 회사 계정) 로그인 → `radio-policy-internal`(private)·
   `radio-policy-data` 두 프로젝트 생성 → `~/work/` 아래에 clone.
6. **Claude 앱 → Code 탭 → 폴더 열기 → `~/work/radio-policy-internal`** 선택. "폴더 신뢰" 확인이
   뜨면 승인. 첫 마디: **"docs/사내이식_계획.md 읽고 시작하자"** (경로는 `../radio-policy-ai/docs/…`
   또는 사내판에 복사해 둔 사본).

3~5의 명령은 Claude 앱을 먼저 연 뒤 세션에게 시켜도 된다.

### 1-4. git 인증 (두 곳, 따로)

- gitlab.com(외부판): 개인 토큰. Windows의 `.gitlab-credentials` 파일은 따라오지 않으므로 맥에서
  credential helper(osxkeychain)로 새로 저장. **외부판 폴더에서 커밋할 일이 생기면 Windows PC와
  같은 저장소의 다른 작업 사본**이므로 CLAUDE.md의 커밋 규칙 3줄(작업 전 `git pull gitlab main`,
  동시 커밋 세션은 하나, 커밋 후 즉시 gitlab·origin 둘 다 push)이 그대로 적용된다.
- gitlab.tde.sktelecom.com(사내판): 회사 계정 토큰.

### B. 사내 조회 계층 (사내에 남는 코드는 반입 잡 하나)

| 구성 | 방법 | 코드 |
|---|---|---|
| 지식 저장소 | Playground Qdrant, 컬렉션 2개: `kb_external`(외부판 반입분)·`kb_internal`(사내 문서) | 없음 |
| 사내 문서 반입 | **Confluence→Qdrant Sync** 컴포넌트 + 스케줄. 가치 있는 사내 문서만 Confluence 페이지로 정리(개인정보 섞인 메일 전량 적재 방지) | 없음 |

| 자문 | 워크플로 `[Chat]→[Qdrant]→[Agent]`(공식 RAG 예시). 시스템 프롬프트는 반출된 `app_config.system_prompt`를 그대로 붙여 넣는다(코드가 아니라 데이터). 근거 규칙 동일: **확정 법령·고시만**, 국회 법안은 KB에 넣지 않는다(외부판 CLAUDE.md와 같음) | 없음 |
| 보고서 초안 | 사내 문서 + Agent. 외부판 #142로 삭제된 기능의 사내 재구현 — 외부판에 코드가 없으므로 **새로 설계**(사내 보고서 샘플은 Confluence에) | 워크플로 |

쓰고 외부판에 역수입 금지.

### C. 데이터 반출·반입 (외부 → 사내, 한 방향)

- **원문·메타데이터만** 반출. `export_document_chunks.py`(외부판 루트, 현재 법령 카테고리만)를
  확장: document_chunks 전량(법령·고시·보도자료·회의록 — `--include-etc`), `app_config` 기준문
  (`system_prompt`·`press_relevance_criteria` 등). 제외 유지: 추가지식(내부 세미나)·ITU-R
  (라이선스 확인 전)·embedding 컬럼·내부 경로.
- **임베딩 벡터는 옮기지 않는다** — 질의 임베딩을 Playground 모델로 만들므로 문서 벡터도
  같은 모델이어야 한다. 반입 잡(§B)이 전량 재생성.
- 반출 자동화: Windows PC 스케줄러에 반출 잡(주 1회) → JSONL 50MB 단위 분할 →
  `radio-policy-data`에 push(이 push만 사람 손) → 사내 CronJob이 pull.
- 검증: 컬렉션별 count 대조 + 표본 10건 내용 일치 + 대표 질의("기지국 개설 허가 절차")의
  검색 결과를 외부판 대시보드와 비교.

### D. 지속 동기화 — 갈라짐이 생기는 곳은 두 군데뿐

- **데이터**(청크·기준문·프롬프트): 반출 잡이 자동으로 따라간다. 외부판에서 청킹·문서 선별·
  프롬프트가 바뀌면 다음 반출에 반영. 갈라짐 0.
- **검색 랭킹**: 외부판은 키워드+의미 하이브리드에 RRF(K=60)·조문번호 등급 가점(`app.js`
  813~870행, `rag.ts`와 동일 유지 #90). 사내는 1차로 Qdrant 의미검색만. 답 품질 차이가 느껴지면
  그때 랭킹 부분만 반입 잡 옆에 1회 이식 — 거의 안 바뀌는 코드다.
- 이식 단위는 커밋이 아니라 **기능**. 사내판 커밋에 외부판 배경역사 번호 인용:
  `이식: 외부판 #90 article_no 등급`. 주기는 정하지 않는다 — 운영자가 트리거.

## 4. 하지 않는 것

- **외부판 시스템 전체를 사내에 복제하지 않는다** — 크롤러·판정·브리핑·국회·관계도·구독 봇은
  외부판에만 있다(2026-09-11).
- 외부판의 대규모 리팩토링(공용 코어 패키지化) — 1인 운영에 추상 계층은 유지비만 늘린다.
- 크롤러를 GitLab CI(어느 쪽이든)로 옮기기 — 매시간 수집은 CI 무료 한도 초과.
- 외부판 키·토큰·챗ID를 사내 저장소에 넣기 — 사내판 시크릿은 Playground KMS에서 새로.
- 사내 문서를 외부판 어디에도 올리지 않기(#142).

## 5. 운영 원칙 (외부판에서 검증된 것 — 그대로 적용)

- 판정·필터·삭제 로직에는 "틀렸을 때 보이는 로그"를 함께 만든다 (조용한 실패 금지).
- `select` 컬럼 목록에 조건 컬럼 누락 금지, 전량 조회는 페이지네이션+`order` 필수.
- LLM 판정 프롬프트에는 시제 가드·현지어 검색 지시 유지 (외부판 #101).
- 문서 규칙: 구조·스케줄·제약이 바뀌면 사내판 CLAUDE.md와 이 문서를 함께 갱신.

### 6-2. 어댑터 교체 표 (코드는 맥북에서 작성 → TDE GitLab push → mydesk에서 배포)

외부판 코드는 어댑터 구조로 분리돼 있다. 갈아끼울 곳:

| 외부판 | 사내판 | 손댈 파일 |
|---|---|---|
| Supabase DB (PostgREST) | PostgreSQL 직결(psycopg) | `sb_client.py` — 스키마는 유지 |
| pgvector `match_chunks_semantic` 등 RPC | Qdrant 질의 | 검색 함수부 — **RRF(K=60)·article_no 가점 등 랭킹 로직은 그대로** |
| Anthropic API 직접 호출 (Haiku 판정·Sonnet 자문) | Agent API Key 게이트웨이 | `crawler.py`의 판정 호출부 등 — **프롬프트·기준문은 에이전트 설정으로 이동, 내용 무수정** |
| Voyage 임베딩 | Playground Embedding Model | `embed_util.py` |
| 텔레그램 (`notify.send_telegram`) | TOKTOK Bot API(p.217) — **발송 전용**, 구독 봇의 양방향 기능은 포기 | `notify.py` |
| PC 스케줄러 + pg_cron | Playground CronJob (Diyfile `cronjobs:`) | 잡 목록은 지침의 pg_cron 표 재사용 |
| 네이버 API 직접 호출 | GW 프리픽스 (`https://outbound-api-gw.playground/openapi.naver.com/...`) | 크롤러 fetch부 |

⚠️ 대시보드(app.js)를 옮긴다면 Supabase 직접 호출부를 사내 Flask API 경유로 바꿔야 한다
(anon key 개념이 없어짐 — 오히려 보안 개선).

### 6-3. 세로 관통 순서

뉴스 크롤러 1개로 **수집(GW)→판정(Agent API)→저장(PG)→알림(TOKTOK)** 1사이클을 성공시킨 뒤
나머지로 확장. 사내판 CLAUDE.md는 외부판과의 **차이만** 적고, 지침·배경역사 문서는 복사해
간다(함정 목록이 그대로 유효). 이식 제외: Supabase Edge Function, 텔레그램 형식, pg_cron 등록,
GitHub/GitLab CI 설정.
