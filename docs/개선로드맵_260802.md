## ③ 법령 개정 diff 자동 브리핑 (규모: ~1일)

**목표**: 관심 법령(전파법·전기통신사업법·정보통신망법 + 시행령·규칙·주요 고시)이
공포되면 "몇 조가 어떻게 바뀌었고 SKT에 무슨 영향인가"를 자동 요약해 발송.

- **트리거**: law_crawler(매일)가 law_amendments에서 단계가 '공포'로 바뀐 행 감지
- **diff**: 법제처 DRF lawService의 연혁 조회로 신·구 본문 확보 → 조문 단위 difflib
  (대시보드 '법령 DIFF 분석' 탭 로직과 형식 통일 — 가능하면 공용화)
- **요약**: Sonnet — 개정 조문 목록 + 변화 요지 + SKT 관점 영향 3줄
- **발송**: 운영자 텔레그램 즉시 + 구독봇 큐(법안동향 토픽) + 대시보드 법령 개정 탭에 기록
- **리스크**: DRF 연혁 API 필드 실측 필요(과거 시행본 조회 파라미터). 고시는 DRF
  admrul 연혁 지원이 약해 1차 범위는 법률·시행령·시행규칙으로 한정.

## ④ 해외 규제기관 모니터링 (규모: 반나절~1일)

**목표**: FCC·Ofcom·BEREC/EC·일본 총무성·ITU 보도자료를 매일 수집 → AI 관련성
판정 → 한글 제목·3문장 요약 → 모니터링 탭 '해외' 필터 + 아침 브리핑 '해외 동향' 1~3건.

- **수집**: foreign_press.py — press_ingest 어댑터 구조 복제. FCC/Ofcom/BEREC는
  RSS(쉬움), 총무성은 HTML(일본어→Haiku가 번역까지). 세션ID·중복 처리 동일 패턴.
- **판정·요약**: Haiku 1콜로 관련성(기존 press_relevance_criteria 해외판) + 번역 + 요약.
  기준문에 **무선국 인허가 제도**(station licensing / wireless telegraphy licence / 無線局免許)
  축 포함 — 단, 제도·규칙 '변경'만 수집하고 개별 인허가 처분 공고(FCC 일일 대량)는 제외
  (운영자 확인 2026-08-02). 일본 총무성은 한국 전파법과 제도가 유사해 비교 가치 높음.
- **저장**: news_feed(source='FCC' 등, urgency 참고) — 60일 롤링 그대로
- **실행 위치**: 해외 사이트라 한국 IP 불필요 → **GitHub Actions 담당**(계정 복구 후,
  매일 05시 — 미국·유럽 발표가 한국 새벽에 몰림). 복구 전엔 PC 임시.
- **비용**: Haiku 일 10~30건 ≈ 월 $1 미만
- **확장(2차)**: 반응 좋으면 주요 문서(주파수 전략서 등)를 KB '해외 정책' 문서로 승격

## ⑤ 과방위 회의록 수집·검색 (규모: 1~2일)

**목표**: 국회 과학기술정보방송통신위원회 회의록을 수집해 "의원별·주제별 발언"을
자문에서 검색 가능하게. 대관 업무 직접 지원.

- **데이터**: 열린국회정보 API(키 보유, assembly_crawler 재사용) 회의록 목록 +
  국회회의록 시스템 원문(PDF → 기존 pdftotext 재사용). 포맷 실측 선행.
- **가공**: 회의 1건 → 통신·전파·AI 관련 발언 블록만 추출(키워드 1차 + Haiku 2차)
  → KB 문서 '과방위_회의록_{YYYY}.md'에 `## YYMMDD 제N차 (안건)` 섹션 등재 + 임베딩
- **노출**: 국회 법안 탭에 '회의록' 서브 목록(회의일·안건·핵심발언 요약), 자문 RAG 포함
- **리스크**: 회의록 공개가 회의 후 수일~수주 지연됨(속기 완성 주기) — 실시간성 기대치
  명시. 발언자 파싱 품질은 실측 후 조정.

## ⑥ 구독봇 맞춤 알림 — 관심 프로파일 (규모: ~1일)

**목표**: 구독자마다 관심사를 등록하면(예: "위성통신, 28GHz, 알뜰폰") 그 주제의
새 소식만 정시 발송분에 '📌 맞춤' 섹션으로 추가. 전체 공통 긴급 판정과 별개 축.

- **등록**: 봇 `/관심 <자유 텍스트>` → Voyage 임베딩 → telegram_subscribers에
  interest_text, interest_embedding 컬럼 추가 저장. `/관심해제` 지원.
- **매칭**: crawler.py 뉴스 저장 시 기사 임베딩(제목+요약)과 각 구독자 관심 벡터
  코사인 유사도 ≥ 임계(초기 0.55, 보수적) → subscriber_queue에 'custom' 토픽 적재
- **발송**: send-subscriber-briefing이 정시 발송에 맞춤 섹션 합류(즉시 발송 없음 —
  기존 정시 원칙 유지 #44)
- **리스크**: 임계값 튜닝 — 초기엔 과소매칭으로 시작, 봇에 👍👎 피드백 붙여 조정.
  임베딩 호출 증가는 기사당 1회로 이미 계산되는 것 재사용(추가 비용 0에 가까움).

## ⑦ 봇 보고서 요청 /report (규모: 1~2일)

**목표**: 텔레그램에서 `/report 6GHz 동향 2페이지` → 보고서 초안 엔진(운영자 문체
학습 + RAG)이 생성한 Word 파일이 봇으로 도착.

- **권한**: 기존 /ask 승인제(ai_allowed) 재사용 + 별도 일일 상한(예: 3회)
- **구조**: 생성이 수 분 걸리므로 큐 방식 —
  ① 봇이 report_requests 테이블에 요청 적재 + "생성 중, 수 분 내 도착" 응답
  ② PC 워커(신규 report_worker.py, 5분 주기 스케줄러)가 요청을 집어
     보고서 엔진 로직(현재 app.js에 있는 프롬프트·RAG 흐름을 파이썬으로 이식)으로 생성
  ③ pandoc/LibreOffice(설치됨)로 docx 변환 → 텔레그램 sendDocument → 상태 갱신
- **리스크**: PC 가동 의존(꺼져 있으면 지연 — 봇이 대기열 위치 안내). app.js 로직
  이식 시 문체 학습(report_samples)·3채널 개인화 재현 범위를 1차엔 축소(문체+RAG만).
