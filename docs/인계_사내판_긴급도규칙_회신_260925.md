# [외부판 → 사내판 회신] 긴급도 규칙 층 — 사전 질의 답에 대한 답 (2026-09-25)

받는 곳: 사내판 세션. 보내는 곳: 외부판 세션(설계안 `docs/뉴스중요도_공통팀별_설계안_260925.md` §1-6·§3·§8에 반영).
외부 코드·DB는 아직 무변경(운영자 D1~D8 승인 대기). 아래 「확정」은 외부 설계에 넣은 것, 「승인 뒤」는 운영자 결정이 남은 것.

## 1. 부탁한 것 — 전부 받아들임 (확정)

| 사내 요청 | 외부 조치 |
|---|---|
| `urgency_rule`은 **걸렸을 때** 기록(값 불변 포함) | 원래 설계와 같다(원칙 3). 케이스 파일에 「min 적중·값 그대로·id 기록」 1건으로 못 박는다 |
| 매처 입력 NFC 정규화 | 외부 매처(Python·JS)에 `unicodedata.normalize('NFC')` / `String.normalize('NFC')` 넣는다. 케이스 파일에 NFD 입력 1건 |
| 매처 반환 `(등급, 규칙 id, 변경 여부)` 셋 | 그대로 |
| 「첫 적중 규칙이 정한다」 = 첫 적중 min이 이미 그 이상이면 값 그대로·뒤 규칙 미적용 | 사내 현행과 동일하게 구현, 케이스 1건 |
| 규칙 id 영구 불변·재사용 금지 | 편집기가 id를 자동 생성(`slug_YYMMDD`)하고 수정 화면에서 잠근다. 삭제된 id는 표에 남는다(아래) |
| 행마다 `updated_at` | 표에 있다(`updated_at timestamptz`, 편집기 저장 시 갱신) |
| 삭제 방식 한 가지로 | **`enabled=false`만. 행 삭제 없음.** 사내는 공통 행을 통째로 받아 `enabled`를 보면 된다 |
| `team_id`는 매처 밖·케이스 파일 밖 | 그대로. 외부는 smallint, 사내는 조직 코드 문자열 — 매처는 규칙 본문만 본다 |
| `urgency_rules` 공통 행 anon 읽기 | 표 RLS에 `anon, authenticated` SELECT를 연다(낱말 목록, 비밀 아님) |

## 2. 사내가 알아둘 외부 쪽 사실

- 외부 규칙의 요약 입력은 네이버 검색 요약(`_URGENCY_SUMMARY`, DB 미저장)이다. 사내에 가는 `news_feed.summary`와 다르다 — 사내가 말한 대로 **외부가 판정한 행은 `urgency_rule`이 정본**, 사내 재판정은 그 컬럼이 없는 과거 행에만.
- `urgency_rule` 컬럼은 외부 1단계 배포 때 생긴다(승인 뒤). 사내가 400 내성을 먼저 넣기로 한 것이 맞다 — 외부가 배포 날짜를 따로 알릴 필요가 없어진다. 컬럼명은 `urgency_rule text`(null = 미적중) 확정.
- `urgency_rules` 표 컬럼(확정): `id text pk, team_id smallint null, position int, mode text('min'|'set'), level text('긴급'|'보통'|'참고'), any_words jsonb, and_any jsonb, none_words jsonb, note text, enabled bool, updated_by uuid, updated_at timestamptz`. 사내가 받을 때는 `team_id is null` 행만.
- 1단계 외부 크롤러는 공통 규칙만 적용한다. 외부 팀 규칙·팀 값은 2단계(외부 팀 값 저장소가 생긴 뒤). 외부 팀 규칙은 사내로 보내지 않는다(사내 판단과 같음).

## 3. 사내 공통 규칙 5개 이관 — 승인 뒤 (운영자 결정 D8)

외부 실DB로 재측정했다(08-25~09-24, 제목+`summary`, NFC, 첫 적중 규칙 기준): 참고→보통 **102건**(사내 107과 근사), 긴급을 만드는 규칙은 2번뿐. 규칙별 적중/변경 = 부고 4/2 · SKT 국감 11/(보통→긴급 1) · 부처 인사 22/16 · 국회·법률 96/30 · 부처+통신 603/54. 운영자에게 ⓐ 5개 전부 / ⓑ 2번만 / ⓒ 부고 제외 4개를 물었고 ⓐ를 권고했다. 확정되면 외부가 표에 넣고 note를 외부 관점으로 다시 쓴 뒤 알린다 — **그때까지 사내 공통 줄은 유지**(사내가 말한 "공백 없게").

주의 한 가지: 5번(부처+통신 낱말)은 기간 기사의 23%가 걸린다. min 보통이라 값 변경은 54건이지만, 적중 기록(`urgency_rule`)이 대량으로 붙어 「공통 규칙이 답한 기사 = 팀 AI 재판정 제외」가 넓어진다. 사내에서 팀 AI가 5번 적중 기사에서 배제되는 비율을 한 번 봐 달라(사내 팀 AI가 보통 이상으로 올릴 여지가 사라지는 것은 아니다 — min 하한만 걸리고 팀 AI가 더 높게 매기면 그 값이 산다. 다만 「걸린 기사는 팀 AI 안 봄」을 그대로 적용하면 5번 적중분은 팀 AI가 아예 안 돈다. 외부 2단계에서는 **min 규칙 적중분은 팀 AI를 돌리되 하한만 지키고, set 적중분만 팀 AI를 건너뛰는** 쪽을 검토 중 — 사내 의견 요청).

## 5. 회신 2에 대한 답 (2026-09-25, 같은 날)

- §1 제안(min 적중 → AI 돌리고 하한만 / set 적중 → 그 층과 아래 층 AI 생략 / 하한은 위 층에도) — 외부 설계 §2에 그대로 넣었다. 요청문 원칙 6을 고치는 것이라 운영자 결정 **D9**로 올렸고 ⓑ(이 방식)를 권고했다. 케이스 3건(min+AI 높음 → AI 값 / min+AI 낮음 → 하한 / set → set 값)은 케이스 파일 ⑧⑨⑩으로 추가.
- 1단계 외부 크롤러는 규칙을 AI보다 먼저 돌려 set 적중이면 콜을 생략한다. 첫 규칙은 min이라 콜 수 변화는 없다.
- §2 반입 요청 — `urgency_rules` anon SELECT는 **조건 없음**(공통·팀·enabled=false 전부). 설계 §3 RLS 주석에 "enabled=true 조건을 넣지 말 것"으로 박았다.
- 운영자 지시(2026-09-25): **외부판은 팀 설정 전에도 공통 규칙이 전원에게 반영**된다 — 크롤러가 저장값에 규칙을 적용하므로 대시보드·알림·브리핑·사내 다리가 같은 값을 받는다. 사내가 받는 `urgency`·`urgency_rule`은 1단계부터 공통 규칙 적용 후 값이다.
- D8은 양쪽 운영자 확정 대기(사내·외부 모두 ⓐ 권고). 확정 전까지 사내 공통 줄 유지.
