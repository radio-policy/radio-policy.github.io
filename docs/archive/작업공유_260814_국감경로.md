### 데이터 무결성 검증에서 나온 것 — **처리 완료**
- ✅ **섹션 3건 복구.** 중복 정리 DELETE가 이웃 섹션 꼬리까지 지워 본문이 잘려 있었다
  (2017.md 2건·2020.md 1건). **섹션 개수는 98/98로 멀쩡해 보였다** — `chunk_index` 결번으로만 드러난다.
  776자→**27,360자** / 764자→**7,137자** / 759자→**7,781자**, 결번 SQL **2문서 → 0**.
  삭제 시 "범위 내 `## ` 헤더가 정확히 1개인가"를 먼저 검사해 같은 사고의 재발 경로를 막았다.
- ✅ **빈 껍데기 섹션 재생성**(`241021` 274자→8,987자) + `shell_section_range()`로 다음 실행 자동 복구.
  ⚠️ 단 **새 본문도 껍데기면 그대로 둔다** — 안 그러면 매 실행마다 chunk_index를 갈아엎고 재임베딩을 유발한다.
- ✅ **질의·응답 부착률 30.4% → 77.4%**(같은 의원 `▶` 연속 31.0% → 9.5%). `MIN_SUBSTANTIVE_LEN=60`이

  ⚠️ 기존 ~200개 섹션은 옛 규칙 본문 그대로다(전면 반영하려면 전 섹션 재등재 + 대량 재임베딩).

  **위 잘린 섹션과 증상이 똑같은 두 번째 경로**였다. 한 번만 받으면 잘린 채 등재되고 dup으로 굳는다.

### **아직 남은 것** — 메인 세션이 판단할 몫
1. **상임위 섹션 111건은 구형 `관련 발언:` 평면 나열 그대로다.** 국감 95건만 `질의·응답:` 구조로 재작성했다.
   절차성 발언도 상임위 쪽엔 41건 남아 있고, 요약(`요약:`) 없는 상임위 섹션도 40건이다.
   고치려면 **뷰어 원문 111건 재수집(수 시간) + 대량 재임베딩**이 필요하다. 이번 ↳ 부착률 개선도
   재등재해야 반영된다(현재 DB 전수 33.0%, 새 코드로 만든 4개 섹션만 77%대).
2. **국감 요지는 인용문이라 보고서에 그대로 못 쓴다.** 2024년 이후 상임위는 Haiku 3인칭 요약이라 인용 가능하지만,
   국감·구년도는 `extract_gist()` 인용문("그런 것이 현실적인 대안이 아닌가 이렇게 해서 물어보는 겁니다")이다.
   품질을 올리려면 유료 AI가 필요해 **운영자 승인 사항**이다.
3. **한자 발언자 4명(85행)은 한글로 검색되지 않는다.** 이름 한자→한글 매핑표가 필요하다.
4. **빈/헤더 청크가 RAG 상위에 든다.** `# 과방위 회의록 2026년 > 출처:` 같은 파일 헤더 청크가 trgm 상위 진입.
   아래 SQL로 내릴 수 있으나 **실행하지 않았다 — 운영자 판단 필요**:
   ```sql
   update document_chunks set is_approved = false
   where doc_category='회의록' and chunk_index = 0 and content like '# 과방위 회의록%';
   ```
5. **RAG 시점 오염** — 정책명 없는 막연한 질의("현재 통신 정책의 최신 쟁점은")에서 2017년 발언이 5위로 올라온다.
   회의록 청크 `content`에 날짜가 없는 게 원인. **프롬프트에 "회의록 인용 시 연도·대수 병기" 한 줄이 가장 싸다.**
6. **assem 파싱 정확도는 47.5% → 77.1%**(신규 35질의, 부분정답 포함 88.6%). 위 수정 뒤 다시 오른다.
   남은 실패 유형 둘: ①**두 낱말 상한이 '앞 두 낱말'만 취해 변별어를 버린다**(`이동통신 기지국 전자파 우려`
   → `이동통신 기지국`, 정답은 `기지국 전자파`). 길이·순서 어느 기준도 반례가 있어 **손대면 회귀 위험**이 크다.
   ②도메인 밖·영어 질의는 0건 대신 수백 건의 무관한 결과를 낸다(`탄소중립 시멘트` → `탄소중립` 224건).
   ①은 의미 판단이 필요해 규칙으로는 한계다. **페이징(240건 상한)·문맥 부착은 실측상 이상 없다.**
7. **`admin-daily-report`는 아직 한 번도 실행되지 않았다.** 첫 발송은 **2026-08-15 09:00 KST**. 그때 실물 확인 필요.
8. **`logUsage` 경로는 프로덕션 실행 이력이 아직 0건**이다(현재 8행은 전부 소급 백필). 첫 실사용 후 확인할 것.
9. **임베딩 대기가 전체 2,806건**(회의록 171건 포함). 이번 작업으로 생긴 건 회의록 171건뿐이고
   나머지 2,635건은 **이전부터 밀려 있던 것**이다. 17시 체인의 `backfill_embeddings.py`가 이 속도로는
   못 따라잡고 있다는 뜻이라 **원인 확인이 필요하다**(대기분은 시맨틱 검색에 안 잡히고 trgm으로만 잡힌다).
   Voyage는 지침상 무료 2억 토큰 범위다.

## 4. 이 작업에서 확정한 사실 — 같은 조사 반복 방지

- 열린국회 `ncwgseseafwbuheph`는 **`CLASS_NAME='상임위원회'`만** 반환한다. **국정감사는 통째로 없다.**
  국감은 국회회의록시스템 검색(`record.assembly.go.kr/assembly/mnts/search/search.do`)뿐이다.
- `collection`은 `record2`(상임위)/`record5`(국감). `record`로 보내면 **200 + 빈 `{}`** — 결과 없음과 구분 불가.
- `CMIT_CD`는 대마다 재배정: 상임위 `20-2-AB`·`20-2-RN`·`21-2-AF`·`22-2-AF` / 국감 `20-5-AB-0`·`20-5-RN-0`·`21-5-AK-0`·`22-5-AG-0`. **콤마 다중 지정 가능.**
- `S_TH/E_TH`는 검색폼 대수코드(**22=제20대, 23=제21대, 24=제22대**) — 열린국회 `DAE_NUM`과 다른 체계.
- **날짜 범위를 안 주면** 최신순으로만 훑어 과거 연도가 페이지 상한 밖으로 밀려 **조용히 0건**이 된다.
- 뷰어 `MNTS_ID`(국감)와 `CONFER_NUM`(상임위)은 값이 겹칠 수 있어 `confer_num`을 **`audit-{MNTS_ID}`**로 네임스페이스했다.
- Edge 런타임에 **DOMParser가 없다** — 뷰어 HTML은 정규식으로 파싱한다.
