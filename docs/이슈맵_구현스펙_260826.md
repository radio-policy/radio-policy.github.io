# 이슈맵 구현 스펙 (2026-08-26 구축 — 배경역사 #110)

> **핵심 원칙: 이슈가 뉴스 보존의 기준이다 — 이슈에 연결된 기사는 자동 잠금(locked)되어 60일 삭제에서 빠지고, 60일 밖의 과거는 재수집·세션 리서치로 복원한다.**

중요 뉴스가 발생하면 과거 유사 사례·관련 법령·이해관계자·SKT 영향을 한 화면에 보여주는 기능.
기획 원형: `docs/차별화_아이디어_요청_개요.md` 아이디어 B + `docs/종합평가_260802.md` C6.
운영자와의 일문일답으로 확정한 결정 전체는 계획 파일(세션 플랜)과 배경역사 #110에 기록.

## 🚀 새 세션에서 이 기능을 손보려면 (복사용 지시문)

```
이슈맵 기능을 수정하려고 해. 먼저 docs/이슈맵_구현스펙_260826.md 를 읽어.
```

작업 세션에 미리 일러둘 것: ①배포 시 `index.html` 캐시버스터 갱신 ②`git add`는 파일명 지정 ③Edge 함수 수정 시 CLI 배포(`operator-webhook`은 `--no-verify-jwt` 필수) ④크롤러 수동 실행 전 HTTP(S)_PROXY 해제.

|---|---|---|
| 메뉴 위치 | 사이드바 독립 메뉴 '이슈맵' (통합 모니터링 바로 아래) | 처음엔 모니터링 그룹 탭 → 운영자 지시로 승격 |

| 사후 처리 | 영구 보관 + 해소 시 사례화. 삭제 기능 없음. 종결유형(resolution_kind) 기록 | 휴면 90일 → "자연 소멸 종결?" 텔레그램 제안 |

## 1. 데이터 모델 (마이그레이션 `issuemap_p0_schema`·`issuemap_p1_rls_policies` 적용 완료)

- **issues**: id, title, definition, category(주파수/규제·CR/사업·서비스/보안·개인정보/기타),
  state(proposed/active/rejected/archived), stage(발생/현안/해소), dormant(휴면 배지),
  stage_log jsonb(자동 전환 이력 [{at,from,to,signal}] + resolve_proposed 마커),
  resolution_kind(법령 시행/처분 확정/자연 소멸/타 이슈 흡수), norm_key(재제안 억제),
  proposal_reason jsonb, source(auto/manual), embedding vector(1024, voyage-4-lite),
  impact_summary jsonb({what,why,action,sources[],model,generated_at}), impact_history jsonb(≤5),
  last_activity_at.
- **issue_links**: issue_id FK(cascade), item_type(news/law/bill/diff/press_chunk/minutes/briefing/kb_case/stakeholder),
  item_id text(타입별: news_feed.id(uuid)/kb_documents.dedup_key/bill_no/law_diffs.id/document_chunks.id/doc_name/식별슬러그),
  item_date(타임라인 정렬 — 원본 날짜 복사), title(표시 캐시 — 원본 삭제 후 잔존), note, added_by(operator/auto/ai).
  unique(issue_id, item_type, item_id).
- **news_embeddings**: news_id uuid PK FK(news_feed on delete cascade — 60일 삭제와 자동 연동), embedding vector(1024), HNSW.
- RPC **match_news_semantic**(query_embedding, match_count).
- RLS: 3테이블 모두 조회 공개(anon+authenticated), 쓰기 authenticated(#104 방향으로 기존보다 한 단계 조임). 승인 파이프·자동 연결은 service key 경유.

## 2. 서버 구성요소

| 파일 | 역할 |
|---|---|
| `issue_suggest.py` | 매시 crawler.py 말미에서 호출(try/except 격리, fail-open). 뉴스 재클러스터(news_dedup.cluster_star, **임계 3 유지**)·무보도 규제 발제·기존 이슈 자동 연결·발생→현안 자동 전환·휴면/복귀·90일 종결 제안. `--dry-run` 지원. 제안 확정 시에만 Haiku 1콜 |
| `issue_case_ingest.py` | 사례 md → document_chunks(doc_category='이슈사례') 청킹(700자, press_ingest 규약)·임베딩·적재 + `--issue`로 연결. **벡터 insert 3건씩 분할** — 4만 행+HNSW에서 일괄 insert는 statement timeout(57014) 실측 |
| Edge `operator-webhook` | **`--no-verify-jwt` 배포 필수**(텔레그램은 Authorization 없음). 입구 ①텔레그램 콜백(`X-Telegram-Bot-Api-Secret-Token`=OPERATOR_WEBHOOK_SECRET + chat_id=OPERATOR_CHAT_ID + telegram_updates 중복 차단) ②대시보드 POST(admin JWT). **승인·기각·해소 파이프 한 벌**을 둘이 공유. 승인 시 news-archive-search를 service-role Bearer로 백그라운드 호출(waitUntil) |
| Edge `news-archive-search` | 과거 뉴스 재수집: 네이버 API + 구글 뉴스 RSS(after:/before: 기간 연산자) 병렬 → URL 정규화 dedupe → deleted_news·기연결 제외 → Haiku 관련성 판정(기준문에 이슈 정의 삽입, 실패 시 제목 키워드 폴백) → 자동 연결+본문 summary+locked. 상한 30건, 제외 목록 반환(감사). service-role Bearer는 내부 호출로 인증 갈음 |
| `notify.send_telegram` | `reply_markup` kwarg 추가(2026-08-26) — 인라인 버튼은 **마지막 조각에만** 부착 |

콜백 데이터 규약: `iss|approve|<id>` / `iss|reject|<id>` / `iss|resolve|<id>` / `iss|keep|<id>`.
운영자봇 웹훅: `setWebhook(url=…/operator-webhook, secret_token=OPERATOR_WEBHOOK_SECRET, allowed_updates=["callback_query"])` 설정됨 — 운영자봇의 push(sendMessage)는 영향 없음.

## 3. 프론트 (app.js — 이슈맵 블록은 `ISSUE_STAGES` 선언부터 `escHtml` 직전까지)

- 탭 등록: `PAGE_TO_NAV.issuemap`, index.html 사이드바 `data-nav="issuemap"`, `go()`→`loadIssueMap()`.
- 목록 `renderIssueMapList()`: 필터 칩(상태·카테고리)+수동 등록 → admin '제안 대기' 박스(승인/기각) → 활성 카드 그리드(stage 배지·🔥·💤) → 휴면·해소 접힘.
- 상세 `showIssueDetail()`: 헤더 → 관계도(`renderIssueMiniMap` — 정적 SVG 박스형, 법령·DIFF·사례는 개별 노드, 기사류는 '언론기사 N건' 묶음 노드. **개별 기사를 노드로 뿌리면 hairball**) → 타임라인(날짜+종류 묶음, 대표 1건+'외 N건', 연도 구분선, '과거 뉴스 보강' 버튼) ‖ 관련 법령 칩(개정 배지) → 이해관계자 카드 → SKT 영향 요약 → 과거 유사 사례.
- 클릭 동선은 앱 안에서 완결: `openIssueLinkItem()`이 타입별 상세(뉴스 본문/DIFF 조문/보도자료 섹션/법안/법령 KB 요약 `renderMd`)를 이슈맵 안에서 연다. 묶음 노드 → `showIssueTypeList()`.
- 승인/기각/해소 `decideIssue()`: **operator-webhook 호출**(직접 DB update 아님 — 텔레그램과 로직 한 벌).
- `enrichIssueArchive()`: news-archive-search 호출, 결과·제외 목록 표시.
- 뉴스 상세 진입점: `showNewsDetail` 하단 '이슈에 연결'(`linkNewsToIssue` — 연결+잠금 동시).
- 항목 라벨은 출처 명시: 언론기사/정부 보도자료/국회 회의록/내부 브리핑(`ISSUE_ITEM_TYPES`).
- 마크다운 본문은 `renderMd` + `.md-body` CSS(styles.css — `#kb-doc-body` 규칙에 병기. **표 스타일 선택자 미confirm 함정 3회째**).

## 4. 운영 절차

- **과거 사례 만들기(세션 수동)**: 세션에 "이슈 N 과거 사례로 ○○ 리서치해서 적재해줘" → 세션이 웹 리서치 → 표준 md(개요/기간/경과 타임라인/관련 법령·고시/이해관계자/시사점/출처) → `python issue_case_ingest.py 사례.md --title "…" --issue N`.
- **해소·사례화**: 대시보드 단계 셀렉트 또는 텔레그램 [자연 소멸로 해소]. 사례 아카이브 적재는 세션에 "이슈 N 사례화해줘"로 요청(자동화는 후속 과제).
- **제안 처리**: 텔레그램 버튼은 만료 없음 — 나중에 눌러도 된다. 기각=재제안 차단이므로 무관 제안은 적극 기각(그게 학습).
