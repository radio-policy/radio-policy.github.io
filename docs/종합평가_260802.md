> 7개 영역(프런트·수집·RAG·텔레그램·벤치마킹·기회발굴·보안)을 병렬 심층조사한 결과의 종합.
> 각 영역은 코드 전수·실DB 조회·브라우저 실측·웹 검색으로 뒷받침됨. 추측과 확인을 구분해 기술.

## 0. 총평

**기능 완성도와 도메인 정합성은 동종 1인 운영 시스템 대비 이례적으로 높다.** 조문 DIFF 자동
분석(+SKT 영향), 무음 실패 방어(heartbeat·🕊️무뉴스 통지·fail-open/closed 구분), 사고 기반
런북(지침·배경역사 #번호 체계)은 상용 제품·업계 관행과 동등하거나 앞선다. 최근 작성 코드는
이스케이프·캐시·에러 처리를 모두 지킨다.

**실제 위험은 코드 실력이 아니라 세 가지 구조적 지점에 몰려 있다:**
1. **초기 로드 낭비** — 페이지당 6MB 중 4.3MB가 깨진 쿼리 폴백(순수 낭비, 1줄 수정으로 소멸).
2. **오래된 렌더 코드의 XSS + 브라우저 키 노출** — 최근 코드는 안전하나 구코드에 소급 미적용.
3. **실행 기반 이중 흔들림** — GitHub 계정 정지 + 노트북 전원/스케줄 문제가 동시 발생 중이고,
   감시자(워치독)가 그중 하나(GitHub)에 얹혀 있어 함께 죽음.

개선안의 대부분은 "새 규칙 도입"이 아니라 **이미 시스템 안에 있는 표준을 구코드·빈 곳에 소급**하는
것이다. 이것이 이 시스템의 가장 큰 자산.

## 1. 영역별 핵심 발견

### 1-1. 프런트엔드 (성능·UX·접근성·XSS)

**성능 — 실측:** 페이지 진입 시 Supabase 27요청 + CDN 2.25MB, 마지막 응답 5.8초.
- 🔴 **보도자료 로더의 정규식 필터가 항상 실패**(app.js:5267, `'~'` 연산자를 PostgREST가 파싱 못함)
  → 전량 조회 폴백으로 **22요청·4.34MB·3.96초를 매 페이지 로드마다** 소모. 게다가 진입 시 무조건 호출
  (app.js:8304)이라 보도자료 탭을 안 여는 사람도 부담. **수정: `'~'`→`'match'` + 호출을 탭 진입 시로 이연.
  실측 검증: 22→2요청, 4.34MB→0.75MB, 3.96초→0.81초.** (10분)
- 🔴 **loadNews `select('*')`** 가 본문(928KB) 포함 1.56MB 수신 — 목록엔 본문 미사용. 컬럼 명시로 −64%. (30분)
- 위 둘만으로 초기 로드 **6MB→0.6MB, 5.8초→1초 미만**.
- 🟡 보도자료 상세가 문서 전체(1.13MB) 받아 2KB 표시 → 서버 필터로 −99.9%. 탭 재진입 캐시 없음(로더 6종).

**보안 — 실행 확인된 XSS:** 뉴스 title/summary가 이스케이프 없이 innerHTML(app.js:2465·2466).
크롤러가 외부 기사 제목을 그대로 저장하므로 악성 제목 주입 시 실행. **localStorage에 Supabase anon 키 +
Claude API 키 보관** → XSS = 키 유출. `renderAssemblyBills` 등 최근 코드는 이미 escHtml 적용 — 구코드
9개 렌더러에 소급하면 됨. (중)

**모바일 375px:** 🔴 기관 필터 2종(정부 8·보도자료 7)이 CSS로 숨겨짐(styles.css:241) — 오늘 상위탭
승격 이후 재검토 누락. 🔴 삭제/잠금 터치 타깃 11×15px(삭제는 확인 없이 즉시 실행). 조문 DIFF 표는 합격.

**접근성:** 키보드로 화면 전환 불가(클릭 대상 3,106개 중 탭 도달 8개), role/tabindex 0개. 사이드바·탭
19개에 tabindex+role만 넣어도 전 화면 도달 가능. `--text-tertiary #999` 대비 2.85:1 → `#6e6e6e` 한 글자로 해결.

**UX:** 🟡 가장 많이 쓰는 뉴스(747건)에 검색창 없음(지식베이스 5탭엔 있음) — 데이터가 메모리에 있어
클라이언트 필터 20줄. 모달 6종 Escape 미지원. 그룹탭 건수 배지 없음.

**죽은 코드:** 함수 5개 + 보고서초안 패널 711줄(도달 불가). app.js 8~9% 감량 가능.

**핵심 제안:** 숨긴 보고서 엔진 재활용한 **의견서 초안 자동 생성**(proposed DIFF 전/후 조문+영향 →

**정직한 반려 3:** 법안 통과확률 예측(표본 없음 — 229건 중 168 미결·가결 2), 협업 스위트(로그인

## 3. "우리가 잘하고 있는 것" (유지·확산)

1. 주석이 사고 기록으로 살아 있음(#번호 체계) — 다음 사람이 같은 함정 회피.
2. 최근 코드는 이스케이프·캐시·에러처리 표준 준수 — 개선 = 구코드 소급.
3. 판정 로직 공유 함수화(_billCommentOpen 등) — 통계·목록 불일치 구조적 차단.
4. 네트워크 실패를 무음으로 안 삼킴 — "고장 vs 조용한 날" 구분 원칙 일관.
5. 빈 상태가 다음 행동 안내("매일 8시 자동 생성").
6. 조문 DIFF+SKT 영향, 무음실패 방어, 런북 — 상용·업계 대비 우위.
