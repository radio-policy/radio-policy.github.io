## 1. 가져갈 파일 (외부 저장소 그대로 복사, 고치지 말 것)

| 파일 | 내용 |
|---|---|
| `urgency_rules.py` | Python 매처. 표준 라이브러리만. `normalize_text` · `match_urgency_rules(rules, title, summary) -> {id, mode, level} | None` · `combine(hit, ai_level) -> (등급, id|None, 변경 여부)` · `apply_urgency_rules(rules, title, summary, ai_level)` · `validate_rules(rows) -> [오류 문장]` · `URGENCY_RULES_FALLBACK`(비상 사본, 아래 5행과 같음) |
| `supabase/functions/_shared/urgency_rules.js` | 같은 규칙의 JS판(`globalThis.UrgencyRules` / `module.exports`). 반환은 `{level, ruleId, changed}` |
| `tests/fixtures/urgency_rules_cases.json` | 공용 케이스 20건 `[{name, rules, title, summary, ai, expect:{level, rule_id, changed}}]`. **사내 이식본도 이 파일 전건을 통과해야 한다.** ⑦ NFD 케이스 2건의 제목·요약은 자모 분리 문자열 — 편집기로 열어 저장하면 NFC로 바뀌니 파일은 복사만 할 것 |
| `tests/urgency_rules.test.js` | node 러너(참고용) |

매처 계약(확정): 입력 = NFC(제목 + ' ' + 요약), 부분 문자열·대소문자 그대로. 적중 = any 하나 이상 AND and_any 각 그룹 하나 이상(평면 배열 = 그룹 하나) AND none 없음. 목록 순서의 **첫 적중 규칙 하나가 정한다** — 첫 적중이 min이고 이미 그 이상이면 값 그대로·id 기록·뒤 규칙 안 봄. min = 하한(AI는 돈다, 결과 = max), set = 지정(그 층 AI 생략). 규칙 한 개는 표 행 모양(`any_words`/`none_words`/`mode`/`level`)과 JSON 모양(`any`/`none`/`"min": 등급`) 둘 다 받는다. `team_id`·`enabled`·`position`은 매처가 보지 않는다(목록을 만드는 쪽이 거르고 정렬).

## 2. 외부 표 `urgency_rules` (사내 다리가 anon 키로 읽는다)

```sql
create table public.urgency_rules (
  id          text primary key check (id ~ '^[a-z0-9_]+$'),   -- 영구 불변, 재사용 금지
  team_id     smallint references public.teams(id),            -- null = 공통 (사내는 null 행만 받는다)
  position    int  not null default 100,                       -- 작을수록 먼저
  mode        text not null check (mode in ('min','set')),
  level       text not null check (level in ('긴급','보통','참고')),
  any_words   jsonb not null,          -- 비지 않은 배열
  and_any     jsonb not null default '[]',   -- [["국감","국정감사"],[...]] (평면도 허용)
  none_words  jsonb not null default '[]',
  note        text not null default '',      -- 화면 「규칙: note」
  enabled     boolean not null default true, -- 삭제 대신 끄기
  updated_by  uuid,
  updated_at  timestamptz not null default now()   -- 트리거가 매 수정 시 now()
);
```

- RLS SELECT: anon·authenticated **조건 없음**(꺼진 행 포함). 사내 다리 요청: `GET /rest/v1/urgency_rules?team_id=is.null&order=position,id` (anon 키). 사내 표에서는 `enabled=false` 행을 「원본에서 꺼짐」으로 표시하고 적용 목록에서 뺀다.
- **행 삭제는 없다** — 끄기(`enabled=false`)만. id는 바뀌지 않는다. 사내 「다르게」 사본은 id로 원본을 가리키고 `updated_at`이 사본 기준 시각보다 새로우면 「원본이 바뀜」을 띄우면 된다.
- 외부 팀 규칙(team_id not null)은 사내로 보내지 않는다(외부 팀 ≠ 사내 조직).

## 4. `news_feed.urgency_rule` (외부 1단계 배포로 생김)

- `text`, null = 미적중. 외부 크롤러가 **값이 안 바뀌어도 적중이면 기록**한다. 외부 판정분은 이 값이 정본 — 외부 규칙은 네이버 요약(DB 미저장)을 보고 사내가 받는 `summary`와 텍스트가 다르므로, 사내는 이 값이 있는 행을 다시 판정하지 않는다.
- **과거 60일 재적용 완료**(2026-09-25 03:1x KST): 적중 1,177행에 기록, 그중 등급 상향 160행(참고→보통 159·보통→긴급 1 「통신 3사, CISO급 나란히 국감행…」). 사람이 고친 행은 등급을 건드리지 않았다. 스냅샷·다리 델타가 `updated_at`이 아니라 `created_at` 기준이면 이 160행의 새 등급이 사내에 안 들어갈 수 있다 — 사내 다리의 델타 기준을 한 번 확인해 주기 바람(필요하면 60일 전량 한 번 재반입).
- 이 컬럼이 없는 과거 행(60일 이전·외부 크롤러 밖의 수집기 행)은 사내 매처로 재판정해도 된다.
- 사내 다리 `COLS`에 `urgency_rule`을 넣으면 된다(외부 컬럼은 이미 있음 — 400 내성은 그대로 두어도 무해).

## 5. 외부 쪽 적용 방식 (참고 — 사내 공통 AI를 맞출 때)

- 외부 크롤러 `grade_urgency`: 규칙을 AI보다 먼저 맞춰 보고 **set 적중이면 공통 AI 생략**, min 적중이면 AI 뒤 하한. 현재 5행은 전부 min이라 콜 수는 그대로다.
- 규칙을 편집하면 **다음 수집(10분)부터 새 기사**에 적용된다. 과거분은 외부 운영자가 `tools_urgency_rules_backfill.py`로 따로 돌린다.
- 외부 편집기 위치: 뉴스 화면 머리줄 「긴급도 설정」 버튼이 여는 창(로그인 전용, 공통은 관리자만 편집, 「내 팀」은 2단계). 사내 콘솔 편집기에서 공통 행은 회색·열람 전용으로 두고 "외부 대시보드에서 관리"라고 적으면 된다(설계안 §8 조건 2).

## 6. 사내 할 일 (설계안 §8 그대로)

1. 매처 두 파일·케이스 파일 복사 → 사내 테스트에서 케이스 20건 통과.
2. 다리에 `urgency_rules` 공통 행 반입(파일 통째 교체, 실패 시 직전 파일 유지) + `news_feed.urgency_rule` 컬럼 반입.
3. 사내 세 지점(적재 색인·콘솔 화면·알림 앱)을 매처 하나로. 외부 `urgency_rule`이 있는 행은 공통 규칙 재판정 생략.
4. 외부 반입 1회 성공 확인 → 사내 공통 규칙 줄 삭제.
5. 콘솔·알림 전체 기사 대조 불일치 0.
